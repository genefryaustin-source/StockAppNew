# Sprint L2.6 — Production Readiness

L2.6 completes the L2 workflow foundation by adding persistent overrides,
persistent notification-delivery records, backup exports, retention dry-runs,
and production verification.

## Added

- SQL-backed legal access overrides
- SQL-backed notification delivery records
- Idempotent persistent notification delivery
- Delivered and failed delivery states
- Persistent operations runtime
- Legal backup archive with checksum manifest
- Retention dry-run planner
- Legal Backup & Recovery dashboard
- Persistence verification script

## Production cutover order

1. Apply the L2.3 workflow migration.
2. Apply the L2.6 operations migration.
3. Wire the existing SQLAlchemy `SessionLocal`.
4. Configure the real notification delivery sink.
5. Run `verify-legal-persistence.py`.
6. Seed registered legal documents.
7. Test review, publication, assignment, acceptance, override, and revocation.
8. Test notification deduplication.
9. Generate and retain a backup archive.
10. Keep enforcement disabled until counsel signs off.

## Retention

The retention planner is dry-run only. It does not delete records.
Add deletion or archival only after legal-hold, records-management,
backup, and counsel requirements are approved.
