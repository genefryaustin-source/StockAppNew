# Sprint L2.3 — Persistent Workflow Integration

L2.3 replaces the testing-only memory repository with a production-capable
SQLAlchemy implementation.

## Included tables

- `legal_document_versions`
- `legal_document_reviews`
- `legal_acknowledgements`
- `legal_workflow_events`

## Installation order

1. Copy the L2.3 `modules/legal_portal/` directory into StockApp.
2. Copy the Alembic template into the project's versions directory.
3. Replace the revision and down-revision identifiers.
4. Run `alembic upgrade head`.
5. Wire the existing SQLAlchemy `SessionLocal` into
   `get_legal_workflow_runtime(session_factory=SessionLocal)`.
6. Run the seed helper once.
7. Confirm the persistence panel reports `sqlalchemy`.
8. Test version creation, approval, publication, assignment, and acceptance.
9. Restart Streamlit and confirm the records remain present.

## SQLite and PostgreSQL

The schema uses portable SQLAlchemy column types and works with SQLite and
PostgreSQL. PostgreSQL remains recommended for production concurrency and
durable audit records.

## Important

Do not call `LegalWorkflowBase.metadata.create_all()` during normal production
startup when Alembic owns the schema. Use migrations as the source of truth.
