# Sprint L2.2 — Legal Review and Acknowledgement Workflow

## Workflow states

```text
Draft
  → In Review
  → Approved
  → Published
  → Retired
```

A reviewer may instead request changes:

```text
In Review
  → Changes Requested
  → Draft
  → In Review
```

## Acknowledgement process

1. A legal version is approved.
2. A super administrator publishes it.
3. The administrator assigns acknowledgement requests to users.
4. Users see a pending-acknowledgement banner.
5. Users review the document and accept or decline.
6. The system records timestamp, user, tenant, version, and response status.
7. Audit events are emitted for every workflow action.

## Current persistence mode

L2.2 ships with an in-memory repository so the workflow can be tested
immediately. In-memory records reset when the Streamlit process restarts.

Before production enforcement, replace the repository with a SQL-backed
implementation using the supplied repository protocol and schema guide.
