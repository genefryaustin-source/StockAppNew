# Sprint L2.2 — Recommended Database Schema

The package includes an in-memory repository for immediate testing. Production
acknowledgement and approval tracking requires persistent database tables.

## legal_document_versions

```text
id
document_key
version
status
effective_date
summary
created_at
created_by
approved_at
approved_by
published_at
retired_at
metadata_json
```

Unique constraint:

```text
(document_key, version)
```

## legal_document_reviews

```text
id
document_version_id
reviewer_user_id
decision
comments
created_at
```

Reviews should be immutable after insertion.

## legal_acknowledgements

```text
id
document_key
document_version
user_id
tenant_id
status
requested_at
due_at
responded_at
ip_address
user_agent
metadata_json
```

Recommended unique constraint:

```text
(document_key, document_version, user_id)
```

## legal_workflow_events

Optional immutable event table:

```text
id
event_type
document_key
document_version_id
acknowledgement_id
actor_user_id
tenant_id
occurred_at
metadata_json
```

## Production requirements

- Use database transactions for every workflow transition.
- Prevent publishing unless the version is approved.
- Prevent acknowledgement assignment unless the version is published.
- Preserve all review and acknowledgement evidence.
- Store timestamps in UTC.
- Apply tenant filters to all tenant-scoped queries.
- Restrict workflow administration to super administrators.
